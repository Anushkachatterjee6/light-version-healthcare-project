# T1–T15 visualization completeness audit and implementation

Audit completed against the existing source, the unchanged canonical notebook, actual API responses and the actual frontend JavaScript. The notebook has 79 cells and 31 saved PNG outputs. Its original T1–T6 image/plot cells and the shared T7–T15 analyses were inspected. The root `index.html` is a historical notebook export; the running application serves `frontend/index.html`. The saved PNGs under `artifacts/` are QA records, not a missing static-file gallery.

Before integration, the 15 tutorial endpoints returned **18 PNG plots** in total. After integration, their representative runs return **46 PNG plots**, plus T11 highlighted source text and T10 representative-term cards. The distinct, previously fixed CNN endpoint retains its four plots and individual input/mask/classification previews. No original dataset, notebook, model architecture or weight file was modified. No data downloads, full notebook execution, full-size CNN training, Git commits or pushes were performed.

## Verification scope and inventory status

- **A — Already integrated:** existing API image/plot paths, preserved and verified through the frontend's generated image elements. This is not a browser-pixel verification claim.
- **B — Notebook output missing from website:** existing notebook figures/comparisons had no equivalent tutorial API visualization.
- **C — Computed result requiring integration:** an existing table, label, count, fit, mask or feature result lacked a visualization/response bridge. New charts use that result; model algorithms and evaluation splits are unchanged.
- **N — Not applicable:** the implementation has no such output, required data/labels are absent, or a zero-only chart would convey no additional information. A note/table is used instead of a fabricated graphic.
- **U — Unable to verify:** browser automation is not available in this session. Real browser layout, responsive pixel appearance and native image-load events remain manual checks for every tutorial. This applies to every matrix row below, even when API and DOM tests pass.

The audit does not infer display from the API alone: the live JavaScript integration test runs each tutorial, matches every returned plot to its actual `img.src`, verifies captions and checks specialized content. It uses a minimal DOM adapter with actual HTTP, not a browser engine. Representative generated PNGs were visually inspected separately, which does not verify CSS/browser layout.

## Implementation and response path

The existing `plots: [{title, png}]` contract is retained. New plots use compact PNGs rather than array payloads; optional `caption`, `x_label`, `y_label` and `wide` metadata explain units and layout. The original renderer still builds the same image elements, now also rendering captions and readable missing/decode-error states. Multi-panel MRI figures span the grid; below 1150px chart figures stack. Image width is responsive with automatic height and contained aspect ratio.

T11 adds `annotations: {text, spans}`. Its renderer uses text nodes and `mark` elements, not `innerHTML`; category and possible-negation information are available in titles and the entity table. T10 representative-term cards display the already returned cluster terms/sizes. No word-cloud weights are fabricated.

The MRI bridge reuses existing I/O/preprocessing/SIFT helpers. Notebook CLAHE/bilateral parameters and segmentation-overlay methods are reproduced in a small shared visualization module without executing notebook cells or changing the notebook. Exact-duplicate hashing caches only file digests; file size/mtime changes invalidate the key. The 3D view samples existing positive-intensity voxels, not a trained surface or synthetic volume.

Analytical chart code runs immediately beside its source computation, reusing fitted predictions, PCA, clustering, coefficients and group summaries. It does not retrain models for individual charts. Original computed outputs and splits remain in place. Original curves/projections gain axis units where missing; their underlying data and styling remain the same. No dependency was added.

Default T7–T15 responses explicitly say deterministic synthetic demonstration, seed 42. Uploaded CSV responses say user-supplied, provenance not independently verified. Missing optional operational fields never generate invented bed/cost values. No annotated label-dependent evaluation plots are added to extraction or ranking demonstrations.
